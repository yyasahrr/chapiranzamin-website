# وب‌سایت چاپخانه

سامانه فارسی و راست‌چین ثبت و مدیریت درخواست‌های چاپ و تبلیغات محیطی. رابط
کاربری با Next.js اجرا می‌شود و تمام داده‌ها، احراز هویت و منطق کسب‌وکار از
طریق HTTP به API موجود در `php-backend` واگذار شده‌اند. Next.js هیچ اتصال
مستقیمی به دیتابیس ندارد.

## معماری

```text
مرورگر
  └─ Next.js App Router
      ├─ صفحات عمومی: خانه، خدمات، نمونه‌کارها، تماس و رهگیری
      ├─ صفحات مشتری: ثبت‌نام، ورود، داشبورد و گفت‌وگوی درخواست
      ├─ پنل مدیر: آمار، فیلتر و مدیریت درخواست‌ها
      └─ Route Handlers در src/app/api (HTTP proxy)
          └─ PHP API
              └─ دیتابیس بک‌اند PHP
```

- `src/app`: صفحه‌ها و API routeهای Next.js
- `src/components`: اجزای مشترک رابط کاربری
- `src/lib/php-backend.ts`: واسط HTTP و proxy درخواست‌ها به PHP API
- `src/lib/constants.ts`: برچسب‌ها و توابع نمایشی مشترک
- `public`: فایل‌های استاتیک
- `php-backend`: بک‌اند اصلی PHP و مالک انحصاری دیتابیس

## پنل‌ها

- `/admin`: مرکز کنترل مدیر با سبک رابط Linear/Vercel
- `/admin/login`: ورود مستقل مدیران و کاربران سازمانی
- `/admin/tickets`: تیکت‌ها و گفت‌وگوی سفارش
- `/admin/orders` و `/admin/workflow`: سفارش‌ها و گردش کار کانبان
- `/admin/services`: کاتالوگ، مدل قیمت‌گذاری و فعال‌سازی خدمات
- `/admin/users` و `/admin/crm`: کاربران، مشتریان و سازمان‌ها
- `/admin/finance`: فاکتورها و شاخص‌های مالی
- `/admin/analytics`: گزارش عملکرد و فروش
- `/admin/files`، `/admin/notifications`، `/admin/cms` و `/admin/settings`
- `/blog`: وبلاگ عمومی سئو‌شده و مدیریت نوشته‌ها از CMS
- `/dashboard`: پرتال اختصاصی مشتری و پیگیری مرحله‌ای سفارش
- `/request`: ویزارد ثبت سفارش با برآورد قیمت از کاتالوگ مدیر

قیمت سفارش سمت سرور از مدل قیمت هر خدمت محاسبه و ذخیره می‌شود. مدیر کل می‌تواند
در جزئیات سفارش قیمت نهایی را ثبت کند. نمایش فیلدهای ابعاد، تعداد، متریال، نصب،
مجوز و توضیحات نیز برای هر خدمت از بخش «خدمات و قیمت‌گذاری» قابل تنظیم است.

نقش‌های مدیریتی:

- `admin`: دسترسی کامل و امکان ساخت حساب‌های دیگر
- `content_admin`: دسترسی محدود به CMS، وبلاگ، فایل و اعلان
- `support`: دسترسی محدود به تیکت، سفارش و CRM

## پیش‌نیازها

- Node.js 22.18 یا جدیدتر
- npm
- فقط برای اجرای بومی بک‌اند در production: PHP 8 و MySQL (در توسعه لوکال
  نیازی به نصب PHP/MySQL نیست؛ بخش بعد را ببینید)

## اجرای لوکال

در دو ترمینال:

```powershell
npm install
Copy-Item .env.example .env.local
# برای حالت آماده‌سازی‌شده، .env.local باید شامل PHP_API_BASE_URL=http://localhost:8080 باشد.

# ترمینال ۱ — بک‌اند PHP (بدون نیاز به نصب PHP/MySQL):
npm run backend

# ترمینال ۲ — رابط کاربری:
npm run dev
```

`npm run backend` همان API موجود در `php-backend` را با PHP کامپایل‌شده به
WebAssembly (`@php-wasm/node`) و دیتابیس SQLite اجرا می‌کند؛ در اولین اجرا
وابستگی‌های runner نصب، جداول از `php-backend/migrations/sqlite/schema.sql`
ساخته و مدیر پیش‌فرض توسعه (`09120000000` / `admin123456`) از
`php-backend/.env` بذر می‌شود. فایل دیتابیس در `php-backend/.data/` نگه‌داری
می‌شود (در Git ثبت نمی‌شود). کد PHP همان کدی است که در production روی PHP
بومی و MySQL اجرا می‌شود.

سپس `http://localhost:3000` را باز کنید. اتصال Next.js به بک‌اند را با
`http://localhost:3000/api/health` بررسی کنید؛ پاسخ سالم یعنی
`{"ok":true,"backend":"..."}`.

## فرمان‌های کاربردی

```powershell
npm run dev        # سرور توسعه Next.js
npm run backend    # بک‌اند توسعه PHP (WASM + SQLite) روی پورت 8080
npm run build      # ساخت نسخه production
npm start          # اجرای build تولیدشده
npm run lint       # بررسی ESLint
npm run typecheck  # بررسی TypeScript
npm test           # تست‌های واحد
npm run test:smoke # تست HTTP؛ نیازمند سرور در حال اجرا
npm run test:load  # تست سبک هم‌زمانی؛ نیازمند سرور در حال اجرا
npm run check      # اجرای lint، typecheck، test و build
```

## ایمیل همگانی

ماژول `/admin/emails` برای مدیر کل، امکان انتخاب مخاطبان، پیش‌نویس، ارسال،
اعلان داخل سامانه و گزارش موفق/ناموفق را فراهم می‌کند. مشتریان فقط در صورت
فعال‌کردن رضایت دریافت ایمیل در ثبت‌نام یا پروفایل وارد گروه مشتریان می‌شوند.

برای ارسال واقعی، متغیرهای `SMTP_*` و `EMAIL_FROM_*` را در secret manager یا
`.env.local` تنظیم و در پایان `EMAIL_SEND_ENABLED` را فعال کنید. تا قبل از آن
دکمه ارسال غیرفعال است و فقط پیش‌نویس ذخیره می‌شود. مقدار secretها را در Git
ثبت نکنید.

## بک‌اند PHP

این پوشه API اصلی پروژه با PHP را ارائه می‌کند و مالک انحصاری دیتابیس است.
دستورهای نصب و اجرای آن — هم حالت توسعه WebAssembly/SQLite و هم حالت
production با PHP بومی و MySQL — در
[`php-backend/README.md`](php-backend/README.md) آمده است. Next.js فقط با
`fetch` و از طریق `PHP_API_BASE_URL` به آن متصل می‌شود.

## وضعیت Production

گزارش‌های قدیمی‌تر در پوشه [`docs/audit`](docs/audit) قرار دارند. در معماری
فعلی، Vercel فقط میزبان Next.js است و هیچ متغیر یا اتصال دیتابیسی ندارد.

### دپلوی روی Vercel

برای استقرار این متغیرها را در پروژه Vercel تنظیم کنید:

- `NEXT_PUBLIC_SITE_URL`
- `PHP_API_BASE_URL`

هیچ متغیر اتصال دیتابیسی نباید در Vercel تعریف شود؛ این تنظیمات فقط متعلق به
محیط PHP backend هستند.
# ثبت‌نام و بازیابی رمز با OTP

در محیط توسعه، کد یک‌بارمصرف داخل فرم نشان داده می‌شود. برای محیط عملیاتی
`OTP_SECRET` (حداقل ۳۲ کاراکتر)، `SMS_WEBHOOK_URL` و در صورت نیاز
`SMS_API_KEY` را تنظیم کنید. وب‌هوک پیامک یک درخواست JSON شامل شماره، کد،
هدف و نام قالب دریافت می‌کند.

فایل‌های طرح سفارش در اجرای لوکال به‌صورت خصوصی داخل
`.data/order-uploads` نگه‌داری می‌شوند و فقط مالک سفارش یا کارمند مجاز
می‌تواند آن‌ها را دریافت کند. در استقرار چندسروره این مسیر باید با object
storage خصوصی و پایدار جایگزین شود.
